# 0012 Turn V1.4：持久化状态机与恢复

状态：第一阶段已实现（审批终态、过期校验、文件 Store 原子 claim、真实矩阵测试）。
多审批批次已有基础实现，恢复路径收尾见 [0016](0016-turn-boundary-and-resume.md)。
完整 execution ledger 与进程崩溃恢复仍属于后续 Runtime 工作。

## 目标

Turn 在模型、工具和人工审批之间可以跨进程暂停、恢复、拒绝和过期，
并且恢复不会重复请求模型步骤或重复执行已经确认的工具调用。

## 状态机

Running → PlanningTools → ExecutingBatch → Running(next step)
Running → Completed / Failed
PlanningTools → AwaitingApproval → ExecutingBatch
AwaitingApproval → Rejected / Expired

每个状态边界都能生成 checkpoint。checkpoint 包含 Turn 上下文、当前
Step、批次调用、审批状态、已批准调用、工具结果和下一步编号。

## 必须解决的问题

1. 一个批次中允许、审批、拒绝调用的确定性处理。
2. 多个审批边界按顺序恢复，不重新调用模型。
3. 审批批准、拒绝、过期是显式终态。
4. 恢复请求必须具备幂等键；同一 approval 不得重复执行工具。
5. 工具执行前后记录 execution ledger，恢复时优先读取已完成结果。
6. 进程重启后仅依赖 checkpoint 和 ledger，不依赖内存中的 TurnControl。

## V1.4 范围

- 保留 TurnControl 作为兼容的短生命周期 API。
- durable API 支持多批次、多审批和混合批次。
- 文件 Store 继续作为参考实现，Store 接口支持 claim/resolve 语义。
- 真实测试使用模型生成 ToolCall，不在测试框架中写死调用轨迹。

## 验收

- 双协议、全模型覆盖：单审批、多审批、多批次和混合批次。
- 进程重启后从文件 checkpoint 恢复。
- approve/reject/expire 分别产生正确 Turn 终态。
- 重复 resume 不重复产生工具副作用。
- 篡改 approval、参数、策略版本、过期 checkpoint 均 fail closed。
- 每个 case 的状态和工具轨迹写入临时 JSONL，并与预期轨迹比较。
